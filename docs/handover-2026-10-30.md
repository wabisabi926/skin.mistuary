## 4. 还剩什么（按优先级）

### 4.1 三个新发现的问题 —— **已全部解决**（2026-10-31，提交 `8fd80d8`）

**① 搜索结果的技术标识不显示**

根因**不在皮肤**：`script.mistuary.helper` 的 `FIELDS` 没请求 `MediaSources`，
`kodi.apply_video_info()` 只用 `setInfo("video", …)`，从不调 `addStreamInfo` →
插件条目的 `ListItem.VideoResolution` 全空，皮肤那排胶囊自然塌陷。
修法：helper 补 `MediaSources` + `addStreamInfo("video"/"audio", …)`，新增
`_hdr_type()` 把 Emby 的 `VideoRangeType` 翻成 Kodi 的 hdrtype。
**皮肤侧零改动**——只要条目的流信息有了，`VideoTechnicalFlagsByPrefix` 自动出标识。

**② 电视剧卡片没有 4K / Blu-ray 角标**

那角标**不是皮肤画的**：`media/flags/` 下只有 `ratings/` 和 `starrating/`，全仓 XML 里
没有任何一处引用分辨率/来源角标 → 角标是**海报图本身带的**（Emby 端叠的）。
剧集（Series）级别没有文件流信息，服务端叠不出来，所以电视剧卡片永远没有。
皮肤侧无解，也不再尝试。

**③ 电视剧小组件右侧留白**

两处，性质不同：

| 位置 | 问题 | 实测 |
|---|---|---|
| `Includes_Search.xml` 搜索网格 16101/16102 | 写死 `<width>1780</width>`（1920-140 的老值），2160 屏上内容止于 x=1850，右边空 310 | 截图内容右缘 1627px ÷ 0.879 = 1851 |
| `Includes_Home.xml` 海报 widget 面板 | `left=70 right=70` 是响应的，但卡片槽 240 除不尽可用宽（2160-140=2020 → 8.4 列），第 9 列被裁、后面还留 70 黑边 | 第 9 张只剩 79px，右缘 1835px = 2090 |

修法：搜索网格去掉写死宽度改 `right=70`；卡片槽 **240 → 252**（2160 上 8×252=2016，余 4px，
整排都是完整海报；1920 上 7×252=1764，余 16）。

- 技术标识一格画出 3 颗 / 4 颗 —— 见 `skin-contracts.md` §4.1.1 的三个条件求值坑

## 5. 最重要的一条：分辨率不是 1920

`addon.xml` 声明了 **8 套分辨率**，全部指向同一个 `folder="xml"`：

```xml
<res width="1920" height="1440" aspect="4:3"    folder="xml" />
<res width="1920" height="1280" aspect="3:2"    folder="xml" />
<res width="1920" height="1200" aspect="16:10"  folder="xml" />
<res width="2040" height="1080" aspect="17:9"   folder="xml" />
<res width="1920" height="1080" aspect="16:9"   folder="xml" />   <!-- default -->
<res width="2560" height="1080" aspect="21:9"   folder="xml" />
<res width="2338" height="1080" aspect="19.5:9" folder="xml" />
<res width="2160" height="1080" aspect="18:9"   folder="xml" />   <!-- 这台机器用的 -->
```

**这台机器是 2160×1080（18:9），Kodi 选了 18:9 那套 → 坐标空间宽 2160。**

所以：**任何"铺满屏幕"的控件都不能写死 `1920`**，否则右边会空 240px。
今天有一半时间在查这个（搜索背景右侧一条青绿亮带，就是这个原因）。

规则：

| 场景 | 写法 |
|---|---|
| 铺满屏幕的层 | `<include>FullScreenDimensions</include>` 或 `<width>100%</width>` |
| 居中定位 | `<centerleft>50%</centerleft>`（**父容器必须先有 width**，否则百分比解析成 0） |
| 成对定位（文字 + 底板 / 描边 / 图标） | **两边一起改**，只改一边必然错位 |
| 内容宽度（列表、文本、海报） | 固定值可以，但要确认不依赖屏幕宽度 |

用户明确选择：**保留多分辨率**（不砍成只做 1080p），因为他的屏幕本身就是 18:9，
砍掉会被横向拉伸约 12.5%。

## 9. 今天踩过的坑（别再踩）

1. **给喂给全屏 `multiimage` 的变量加兜底** → 改了所有首页分区的背景。
   典型：`HomeFanartVar`。
2. **只改"文字"不改"底板"** → 首页导航最后一个「文件」掉到胶囊外面。
3. **拿 `param` 的默认值当事实** → 详情页评分行位置写死 158，实际简介高度是 105，
   下方凭空多空 51px。改共享组件位置前必须先列出**所有调用方实际传的参数**。
4. **列表项的 label 不是每帧重算** → 可见性每帧算，但 label 只在条目重绘时解析，
   所以"随状态翻转的文字"会慢半拍（搜索键盘 123/ABC 就是这么废掉的）。
5. **Kodi 的 `aspectratio` 只有 4 种**：`keep` / `scale` / `center` / `stretch`，
   **没有"放大并裁切(cover)"**。全屏背景想铺满只能用 `stretch`。
