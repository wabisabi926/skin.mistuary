## 二、🟡 风险项（6 条）

### 🟡1 两个浮窗缺遮蔽层

**位置**：`xml/Custom_1102_TextViewer.xml`、`xml/DialogContextMenu.xml`

**问题**：有玻璃面板，但既没有 `scrim_*` 也没有 `DialogBackgroundCommons`。播放视频时打开，
底下的画面直接透上来，文字会糊在画面上读不清。

**修复**：在面板之前插一层满屏遮蔽（和别的浮窗一致）。

```xml
<!-- 放在最前面，紧跟 <controls> -->
<control type="image">
    <width>100%</width>
    <height>100%</height>
    <texture colordiffuse="$VAR[NaraGlassFloatScrimVar]">colors/black.png</texture>
</control>
```

> `NaraGlassFloatScrimVar` 跟「浮窗透明度」档走，不要用页面档的 `NaraGlassScrimTintVar`。

### 🟡2 `VideoPlayer.HdrDetail` 不存在

**位置**：`xml/Includes_SettingsDialog.xml:166`

```xml
<label2>...$INFO[VideoPlayer.HdrDetail, P]$INFO[VideoPlayer.VideoResolution, | ]...</label2>
```

**问题**：Kodi 的 `VideoPlayer` infomap **没有 `HdrDetail`**（只有 `ListItem.HdrDetail`，
且只在详情页有列表上下文）。这里永远取到空，`P` 前缀也不会显示 —— 属于死代码。

**修复**：删掉这段，或换成真实存在的 `VideoPlayer.HdrType`。

```xml
<!-- 改前 -->
$INFO[VideoPlayer.HdrDetail, P]
<!-- 改后（二选一） -->
$INFO[VideoPlayer.HdrType, ]        <!-- 只有 HDR/HDR10/DV 类型，没有 P7 档位 -->
（直接删掉）
```

> 杜比视界 P7 / P7 FEL 档位在播放页**拿不到**，这是 Kodi 的限制，皮肤补不了。
> 详情页能显示是因为那里有 `ListItem.HdrDetail`。

### 🟡3 39 处写死 1920×1080

**位置**：`DialogMusicInfo.xml:26-27`、`Custom_1111_MovieSetDialog.xml:20-21`、
`DialogPVRInfo.xml:13-15`、`DialogKeyboard.xml:73` 等，共 39 处

**问题**：`addon.xml` 声明了 8 种画幅（含 21:9 的 2560×1080、4:3 的 1920×1440），
全部映射到同一套 `xml/`。写死 `1920` 的满屏层在 21:9 上右边会空 640px，在 4:3 上下会空。

**修复**：满屏层一律用百分比。

```xml
<!-- 改前 -->
<control type="image">
    <width>1920</width>
    <height>1080</height>
    <texture>...</texture>
</control>

<!-- 改后 -->
<control type="image">
    <width>100%</width>
    <height>100%</height>
    <texture>...</texture>
</control>
```

> 如果确实需要"比屏幕宽一点"（比如铺满的遮罩带位移），用 `left=-120 width=2160`
> 这种超宽写法，而不是 `1920`。

### 🟡4 13 个窗口没有 `<defaultcontrol>`

**位置**：

```
Custom_1109_TopBarOverlay  DialogBusy  DialogConfirm  DialogExtendedProgressBar
DialogNotification  DialogSeekBar  DialogSubtitles  DialogVideoManager
DialogVolumeBar  MusicVisualisation  ...（共 13 个）
```

**问题**：打开时焦点落在"第一个可聚焦控件"，可能是某个按钮而不是列表。
`DialogSubtitles` / `DialogVideoManager` 这种带列表的对话框尤其明显 —— 进来要按一次方向键才进列表。

**修复**：显式指定。

```xml
<window>
    <defaultcontrol>50</defaultcontrol>   <!-- 写列表 / 主控件的 id -->
    <controls>...</controls>
</window>
```

> 纯提示类窗口（`DialogBusy`、`DialogVolumeBar`、`DialogNotification`）没有焦点控件，
> 不加也正常 —— 这类可以不动。

### 🟡5 演员点击依赖公共插件 `script.embuary.info`

**位置**：`xml/Includes_DialogVideoInfo_Cast.xml:45-47`

```xml
<onclick condition="System.AddonIsEnabled(script.embuary.info) + ...">RunScript(script.embuary.info,call=person,query='...')</onclick>
<onclick condition="System.HasAddon(script.embuary.info) + !System.AddonIsEnabled(...) + ...">EnableAddon(script.embuary.info)</onclick>
<onclick condition="!System.HasAddon(script.embuary.info) + ...">InstallAddon(script.embuary.info)</onclick>
```

**现状**：三段保护写得很规范 —— 已装就调用、装了没启用就启用、没装就提示安装。**不会报错**。

**但它和"完全剥离私有依赖"的目标有张力**：没装这个插件的用户，点演员会被弹"是否安装
script.embuary.info"。虽然它是公共插件（不是原作者的私有件），但仍然是**外部依赖**。

**两个选择**：

- **A（推荐）** 保留但写明：README「已知限制」加一条"点演员查看作品需要 `script.embuary.info`"
- **B** 去掉，改成皮肤内本地筛选：

```xml
<onclick condition="!String.IsEqual(ListItem.DBType,set)">ActivateWindow(Videos,filter&amp;role=actor,...)</onclick>
```

> B 的代价：只能筛本地库，Emby 动态节点筛不了。**建议 A**。

### 🟡6 `addon.xml` 的 summary 措辞

**位置**：`addon.xml:22`

```xml
<summary lang="zh">雾汐｜轻量透明皮肤，专为 Emby for Kodi NextGen 优化，支持多评分展示</summary>
```

**问题**："专为…优化"暗示强绑定。实际没有 Emby 也能用，只是少了动态节点和豆瓣评分。

**修复**：

```xml
<summary lang="zh">雾汐｜轻量透明皮肤，可选搭配 Emby for Kodi NextGen，支持多评分展示</summary>
<summary lang="en">Mistuary - Lightweight transparent skin, optionally pairs with Emby for Kodi NextGen</summary>
```

## 三、🟢 优化项（3 条）

### 🟢1 `Includes_DialogSelect` 打开成本高

**位置**：`xml/Includes_DialogSelect.xml`（99 个控件、38 个 `<visible>`、5 组同 id 的 `$PARAM` 组合）

**问题**：每次打开都全量构建。选择列表在 CoreELEC 弱盒子上第一次弹出会有 ~0.2–0.4s 延迟。

**建议**：给列表加 `preloaditems`（只预建可见数量）。

```xml
<control type="list" id="3">
    <preloaditems>2</preloaditems>
    ...
</control>
```

### 🟢2 首页 widget 刷新开销

**位置**：`xml/Includes_Home.xml`（119 个控件、82 个 `<visible>`）

**建议**：widget 的 `visible` 条件里避免叠 `Container(xxx).IsUpdating` 这种每帧求值的表达式；
能挪到 `<onload>` + `Window.Property` 的挪过去。

> 现状 82 个 visible 里多数是 `Skin.HasSetting(...)`，很便宜，**不是必须改**。
> 只有 widget 数量开到 6 个以上时才有感知。

### 🟢3 循环动画（已核查，合理）

| 位置 | 用途 | 判定 |
|---|---|---|
| `DialogBusy.xml:28,37` | 加载转圈 | ✅ 该转 |
| `DialogExtendedProgressBar.xml:38` | 进度转圈 | ✅ 该转 |
| `Includes_Home.xml:1522` | widget 加载 spinner | ✅ 只在加载时可见 |
| `MusicVisualisation.xml:107,116` | 黑胶旋转（24 秒/圈） | ✅ 只在黑胶模式 |

**没有多余的常驻动画**。共 409 个 `<animation>`，其中 269 个无 `condition`，但都挂在
`<visible>` 有条件的控件上，不触发就不跑。
