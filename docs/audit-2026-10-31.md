## 二、语法 & 兼容性

### 🟡 2-1　声明的 Kodi 版本与实际不符（`$MAP` 需要 Kodi 22）

**位置**：`addon.xml:3` + `xml/Includes_VideoTechnicalFlags.xml`（19 处）+ `xml/Includes.xml`（1 处）

**证据**

```xml
<!-- addon.xml -->
<import addon="xbmc.gui" version="5.17.0"/>   <!-- 5.17 = Kodi 21 -->
```

```
$MAP[ 出现 20 次（Kodi 22 才引入）
xml/Includes_VideoTechnicalFlags.xml:359
    <param name="icon" value="$MAP[NaraTechnicalHdrIconMap,$PARAM[hdr_type]]" />
```

`Includes_VideoTechnicalFlags.xml:246` 的注释自己写着：

> 原来按 `$EXP[nara_kodi21]` 在「映射文字」和「原始值」之间二选一……

说明 **Kodi 21 的回退分支已经被移除**，只剩 `$MAP` 一条路。

**后果**：Kodi 21 上，技术标识会显示成 `$MAP[NaraTechnicalHdrIconMap,dv]` 这样的原文
（`$MAP` 在 21 上不展开），而不是 4K / DV / Atmos 图标。**不会崩，但界面是坏的。**

**修法（二选一，推荐 A）**

**A. 明确只支持 Kodi 22**（与现状一致，改动 1 行）

```xml
<!-- addon.xml -->
<import addon="xbmc.gui" version="5.18.0"/>
```

代价：Kodi 21 用户装不上（Kodi 会直接拒绝，比装上了显示乱码好）。

**B. 恢复 21 的回退分支**（工作量大，要改 20 处）

```xml
<!-- 在 Variables.xml 里加一个兜底变量 -->
<variable name="NaraHdrIconVar">
    <value condition="$EXP[nara_kodi21]">flags/hdr.png</value>
    <value>$MAP[NaraTechnicalHdrIconMap,$PARAM[hdr_type]]</value>
</variable>
```

然后 19 处 `<param name="icon" value="$MAP[...]">` 全部改成
`<param name="icon" value="$VAR[NaraHdrIconVar]">`。**注意 `$VAR` 不能带参数**，
每类映射（hdr / dv / audio）都得单独建一个变量。

> 我的建议：**选 A**。项目文档 `HANDOVER.md` §8.7 已写明「Kodi 21 实机验证已放弃」，
> 保留一个没验证过的兼容分支只会制造"看起来支持、实际是坏的"的假象。

### 🟡 2-2　`DialogPictureInfo.xml` 图片预览面板写死 1280 宽

**位置**：`xml/DialogPictureInfo.xml:23`

```xml
<control type="image">
    <left>70</left>
    <width>1280</width>      <!-- 固定值 + 固定左边距 -->
    <height>820</height>
    <include>NaraDialogGlassTexture</include>
</control>
```

**后果**：1920 画布上左边距 70、右边留 570，看起来是"偏左的浮窗"；
到 2160 / 2560 画布上右边留白变成 810 / 1210，**面板越来越偏左**。
不会崩，但 18:9 屏（你的 2160×1080）上很明显。

**修法**：改成居中 + 百分比宽

```xml
<control type="image">
    <centerleft>50%</centerleft>          <!-- 居中，替代 left=70 -->
    <width>66%</width>                    <!-- 1280/1920 ≈ 66.7%，随画布伸缩 -->
    <height>820</height>
    <include>NaraDialogGlassTexture</include>
</control>
```

> 同一个窗口里 `left=120` 的图片容器（第 25 行）也要一起改，否则面板和图片会错位 ——
> AGENTS.md §3.5 的「成对定位必须两边一起改」。

### 🟡 2-3　`AudioChannels` 系列标签带了 `(DefaultLayout)` 参数

**位置**：`xml/Variables.xml:1242-1246`

```xml
<variable name="AudioChannelsVar">
    <value condition="Window.IsActive(fullscreenvideo)">$INFO[VideoPlayer.AudioChannels(DefaultLayout)]</value>
    <value condition="Window.IsActive(visualisation)">$INFO[MusicPlayer.Channels(DefaultLayout)]</value>
    <value condition="Container.Content(albums) | Window.IsActive(10502)">$INFO[ListItem.MusicChannels(DefaultLayout)]</value>
    <value>$INFO[ListItem.AudioChannels(DefaultLayout)]</value>
</variable>
```

**问题**：Kodi 的 `AudioChannels` / `MusicChannels` 是**无参标签**（返回 `5.1`、`2.0` 这类字符串），
`(DefaultLayout)` 不是它们的合法参数。Kodi 对不认识的参数一般是**忽略**，
但不同版本行为不一致 —— 有的返回空串。

**后果（如果返回空）**：`Includes.xml:448` 的 `!String.IsEmpty(ListItem.AudioChannels)`
判断会失败，**音轨标识整颗不显示**。这属于"静默失效"，很难发现。

**修法**：去掉参数

```xml
<variable name="AudioChannelsVar">
    <value condition="Window.IsActive(fullscreenvideo)">$INFO[VideoPlayer.AudioChannels]</value>
    <value condition="Window.IsActive(visualisation)">$INFO[MusicPlayer.Channels]</value>
    <value condition="Container.Content(albums) | Window.IsActive(10502)">$INFO[ListItem.MusicChannels]</value>
    <value>$INFO[ListItem.AudioChannels]</value>
</variable>
```

**验证方法**：进一部 5.1 的片子，看 OSD 右下角有没有 `5.1`。
改之前先看有没有 —— **有的话说明参数被忽略了，这条降级为 ⚪**，别白改。

## 三、资源文件清理

### ⚪ 3-1　英文 po 有 173 条空 `msgstr`

**位置**：`language/resource.language.en_gb/strings.po`

```
条目 245，重复 0，空 msgstr 173
样例：
msgctxt "#31000"
msgid "Now playing"
msgstr ""            ← 空
```

**性质**：`en_gb` 是源语言，`msgstr` 空时 Kodi 回退到 `msgid`，**显示正常**。
只是 gettext 工具链会报警告，且不便于别人接手翻译。

**修法（可选）**：批量把 `msgstr` 填成与 `msgid` 相同

```python
import re, pathlib
p = pathlib.Path("language/resource.language.en_gb/strings.po")
s = p.read_text(encoding="utf-8")
s = re.sub(r'(msgid "([^"]*)"\n)msgstr ""\n', lambda m: m.group(1) + 'msgstr "%s"\n' % m.group(2), s)
p.write_text(s, encoding="utf-8")
```

**其余全部干净**：

| 检查项 | 结果 |
|---|---|
| 未引用贴图（`--orphans`） | **0 张**（749 张全部被引用，已排除动态前缀） |
| 死变量 | **0 个**（287 个定义全部有引用） |
| 死 include | **0 个**（288 个定义全部有引用） |
| 死字符串 | **0 条**（245 条全部有引用） |
| 重复 `msgctxt` | **0 条** |
| 调试 print / 日志 / 荧光色占位 | **0 处** |
| 注释掉的整块代码 | **0 处**（注释都是设计说明，不是废弃代码） |
| 超大素材 | 只有 1 张 >100KB：`media/osd/nara/music-background.jpg` 256.8 KB |

`media/` 总计 11 MB / 749 张，打包后 xbt 8.7 MB —— 对皮肤来说是正常体积。

## 四、性能与渲染（CoreELEC 弱硬件）

### 🟢 4-1　`Includes_Home.xml` 是全皮肤最重的文件

**位置**：`xml/Includes_Home.xml`

| 指标 | 值 | 全皮肤排名 |
|---|---:|---|
| 控件数 | 119 | **第 1** |
| `<visible>` 条件 | 82 | **第 1** |
| 动画 | 19 | 第 3 |
| group 嵌套 | 7 层 | 第 3 |

首页每一帧都要对 82 个 `visible` 求值，其中不少是
`$INFO[...]` + `String.IsEmpty` + `Skin.HasSetting` 组合。

**优化建议**（不是 bug，只在盒子上卡顿时做）：

1. 把重复出现的组合条件抽成 `<expression>`，一次定义到处引用
   （Kodi 对 expression 有缓存，比每处重复求值便宜）
2. 把"只在某个 widget 可见时才需要"的控件，外层包一个 `<control type="group">`
   带同样的 `<visible>`，让 Kodi 直接跳过整棵子树

```xml
<!-- 改前：每个子控件都带一遍长条件 -->
<control type="image">
    <visible>!String.IsEqual(ListItem.Property(node.type),target_folder) + !String.IsEmpty(ListItem.Art(landscape))</visible>
</control>

<!-- 改后：条件只求值一次，子树整块跳过 -->
<control type="group">
    <visible>!String.IsEqual(ListItem.Property(node.type),target_folder)</visible>
    <control type="image">
        <visible>!String.IsEmpty(ListItem.Art(landscape))</visible>
    </control>
</control>
```

### 🟢 4-2　`Home.xml` group 嵌套 8 层

**位置**：`xml/Home.xml`（最深 8 层），`MyPVRGuide.xml` 也是 8 层

Kodi 的 group 会参与坐标计算，8 层不算致命，但每层都会让子控件的坐标
多算一次。**建议不超过 6 层**，超出时检查有没有可以合并的纯定位 group。

### 🟢 4-3　黑胶唱片是常驻旋转动画

**位置**：`xml/MusicVisualisation.xml:107,116`

```xml
<animation effect="rotate" start="0" end="360" loop="true" time="24000" condition="true">Conditional</animation>
```

音乐播放期间**一直转**（24 秒一圈），弱 GPU 上会持续占用合成器。
全皮肤 `rotate` 动画共 11 处，另外几处是 Busy 转圈（短暂）和 PVR 箭头（一次性）。

**建议**：加一个开关，低端盒子可关

```xml
<!-- MusicVisualisation.xml：给旋转加条件 -->
<animation effect="rotate" start="0" end="360" loop="true" time="24000"
           condition="!Skin.HasSetting(no_vinyl_spin)">Conditional</animation>
```

```xml
<!-- SkinSettings.xml：加一行开关 -->
<control type="radiobutton" id="731">
    <label>黑胶唱片旋转</label>
    <onclick>Skin.ToggleSetting(no_vinyl_spin)</onclick>
    <selected>!Skin.HasSetting(no_vinyl_spin)</selected>
</control>
```

### 🟢 4-4　动画总量偏多，但绝大多数是窗口级

| 类型 | 数量 | 说明 |
|---|---:|---|
| `fade` | 229 | 大部分是 `WindowOpen` / `WindowClose`，只在开关窗口时跑 |
| `zoom` | 86 | 焦点缩放，`time` 多为 200ms，可接受 |
| `slide` | 83 | 面板滑入，同上 |
| `rotate` | 11 | 见 4-3 |

**没有发现 `loop="true"` 的 fade/zoom**（除黑胶），所以待机时不会持续掉帧。
`fadetime` 最大 1000ms（1 秒），只有 1 处，可接受。
