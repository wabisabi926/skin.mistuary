### 2.3 本地刮削库的「媒体库」行（已递交 `d8db9cd` / helper `ee1708e`，未推送）

**结论**：官方 Kodi 22 没有 `videodb://medialibraries/`。RC2 用的
`videodb://medialibraries/`、`sources=local`、`ListItem.Property(library.art)`
全是魔改内核能力，官方 K22 不支持，不能照搬。

**做法**：不动 Emby 用户现有路径，新增 helper 目录；再给一个三档设置让用户选来源。

- helper 仓库 `script.mistuary.helper` 新增 `mode=libraries`：
  - `lib/media_libraries.py` 读 `sources.xml` 的 `<video><source>`；
  - 过滤 `emby-for-kodi-next-gen-*` 与 E4K 注入路径；
  - 每个 source 返回一个 `isFolder=True` 的目录项，点击进对应视频源；
  - 已有 `library_icons/<库名>.png` 时作为 `thumb/poster` 交给 ListItem。
- 皮肤 `xml/Home.xml` 两组互斥 include（两页都列，类型由 helper 分流，见 §6.1）：
  - **自动**（默认）：E4K 启用走 `videodb://movies|tvshows/tags/`，否则走 helper；
  - **Emby（E4K）**：强制走 tag，即使同时有本地源；
  - **本地 Kodi**：走 `plugin://script.mistuary.helper/?mode=libraries&type=movies|tvshows`，
    helper 读 MyVideos `path.strContent` 分电影/剧集；未设类型的源只在电影页兜底；
  - `background_art_condition=false`，封面走 `HomeMediaLibraryArtwork` 的
    helper 同步 → 自定义目录 → `extras/artwork/library-default.jpg` 兜底。
- 设置项：`SkinSettings.xml` **媒体页**（不是首页/电影分区）`Skin.SelectBool(31850, 31851|nara_libsrc_auto,
  31852|nara_libsrc_emby, 31853|nara_libsrc_local)`；`Variables.xml` 新增
  `NaraHomeLibrarySourceLabelVar`；切换后 `ReloadSkin()`（include condition 加载时求值）。
  `nara_libsrc_auto` 是恢复默认档，加入 audit 的 `RESET_ONLY_SETTINGS`。
- 入口顺序：`SkinSettings.xml` 媒体分类置顶三项，顺序为
  **媒体库来源 → 自定义媒体库封面目录 → 立即同步媒体库封面**。
  `Variables.xml` 帮助条新增 `Control.HasFocus(628)` → `$LOCALIZE[31854]`；
  封面目录帮助 `31737` 压到 39 字，避免拿分类兜底文案或超长文案。
- `xml/Includes_HomeVideo.xml`：电影页可见性表达式改为 `E4K | helper`；
  电视剧页回退为只认 E4K（helper 不区分媒体类型，重复列会出错）。
- 测试：helper `tests/test_media_libraries.py` + `test_default.py`；
  皮肤 `tools/test_home_libraries_page.py` 新增本地兜底 + 三档设置契约。
- 实机 A/B 已通过：临时禁用 E4K + 本地测试源 → 电影页出现 `Mistuary 本地测试库`；
  还原后恢复 Emby 库（华语电影 / 外语电影 / 动画电影…）。

**注意**：helper 新路由需要发版后才能对普通用户生效。发版时必须：
helper 升版本（建议 0.6.0）→ 皮肤 `addon.xml` 的 helper 下限同步抬高 → 皮肤再发版。

## 3. 踩坑记录（下次省时间）

**① F5 必须先确认 Kodi 是前台窗口**
- 否则 `keybd_event(VK_F5)` 发给别的窗口，日志不会出现新的 `skin loaded`，会误判「改动没生效」。
- 可靠做法：`AttachThreadInput + ShowWindow(9) + SetForegroundWindow + BringWindowToTop`，
  发键后**以 `kodi.log` 里 `skin loaded` 时间戳变化为准**，不要看画面（可能是旧帧）。
- 单次常不生效，需循环重试。PowerShell 的 `Add-Type`、COM(`WScript.Shell`) 都被安全策略拦，只能走 ctypes。

**② `WidgetListCategories` 的 `item_top` 默认 20**
- 卡片从 `item_top` 起画。`item_height` 缩到等于 `card_height` 时必须把 `item_top` 设 0，
  否则卡片下半部超出 panel 被裁——**表现为整行卡片消失**。

**③ `HomeVideoTailRow` 行高是固定值**
- 原本 260，两行 520。`top` 下移后可用高度不足时，「类别」行会被挤出屏幕。
- 行高必须 ≥ `header_height + panel_top + panel_height`。

**④ 隐藏 wraplist 会抢焦点（与轮播不可兼得）**
- 详见 §4.2。官方 K22 上做不了「Hero 自动轮播」。

### 6.6 续播弹窗暂停失效（已修，待递交）
- 根因：`lib/file_resume.py` 用 `PlayerControl(Pause)`；Kodi 的 `PlayerControl`
  没有 pause 命令（只有 play 是播放/暂停切换），未知参数被忽略 → 从未暂停。
- 修复：新增 `_set_paused()` 走 JSON-RPC `Player.PlayPause`（明确 `play=false/true`，
  playerid 从 `GetActivePlayers` 取）；只恢复「我们暂停过」的播放；取消仍 Stop。
- 测试：`tests/test_file_resume.py` 覆盖 play=false/play=true/无视频播放器/RPC 错误，
  并加守卫断言源码里不再出现 `PlayerControl(Pause)`。
- 实机复测（真实按键路径）：弹窗出现后 `speed=0`、时间冻结在 0.155 秒；
  选「继续播放」→ 跳到 4:44 继续播；停止后回首页，状态正常。

### 6.7 本地源类型与 http 过滤（2026-11-20 追加）

- `sources.xml` 的 `<video>` 只有路径；Kodi 新增源时选的内容类型存在
  `MyVideos*.db` 的 `path.strContent`（movies / tvshows / …）。
  JSON-RPC 只有 `VideoLibrary.SetSourceContent`，**没有读取接口**。
- **文件管理器源在 `<files>`，不算视频库源**。本机 `<video>` 目前只有 E4K 注入源，
  所以本地档在这台机器上是空列表（§2.3 的 A/B 测试必须临时加一个视频源）。
- **过滤只看 E4K 标记，不看协议**：`http(s)://` 也可能是正规 WebDAV 库。
  曾加过「过滤 http(s)」并被撤销——依据是错误判断（用正则扫全文把 `<files>` 文件源
  当成 `<video>` 视频源，以为 kodi.emby.tv 会出现在本地档；实际它在 `<files>`，
  helper 只读 `<video>`）。已加单测锁住「WebDAV http 源保留」。
